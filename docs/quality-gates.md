# OPICOC V2 Quality Gates

Before any pull request, module refactor, or feature phase can be merged into the `main` branch, it must satisfy all criteria in this quality gate checklist.

---

## 1. Code Quality & Architecture Gates

- [ ] **TypeScript Strictness**: `tsc --noEmit` passes with 0 errors and 0 warnings. No `any` or untyped assertions.
- [ ] **Linting & Syntax**: `npm run lint` passes without warnings. ESLint rules strictly obeyed.
- [ ] **Dead Code & Imports**: Zero unused imports, orphaned variables, deprecated helper functions, or commented-out code blocks.
- [ ] **Dry Business Logic**: Pricing math, town hall tier lookups, and session validations are imported from domain modules rather than duplicated inline.
- [ ] **Component Sizing**: No single file exceeds 200 lines without documented architectural justification. UI components are broken into composable subcomponents.
- [ ] **Magic Values**: No raw string literals for routes, status codes, query keys, or roles; all reference typed constants in `src/config/`.

---

## 2. UI / UX & Responsiveness Gates

- [ ] **Mobile Viewport (320px – 480px)**: Verified on small phone screens. No horizontal overflow (`overflow-x: hidden`). Touch targets meet minimum 44x44px. Drawer navigation opens and dismisses fluidly.
- [ ] **Tablet Viewport (768px – 1023px)**: Responsive 2-column grids, appropriate font scaling, drawer or desktop header transitions correctly.
- [ ] **Desktop Viewport (1024px – 1440px+)**: Multi-column layouts cleanly aligned with `max-w-7xl` container constraints.
- [ ] **Explicit Loading States**: Skeleton screens implemented for all asynchronous views. No layout shift when dynamic content lands.
- [ ] **Explicit Empty States**: Meaningful empty states implemented for empty search results, empty cart, empty orders, and empty notifications with clear recovery actions.
- [ ] **Explicit Error States**: Error boundaries (`error.tsx`) in place. Human-readable error messages with "Retry" triggers.
- [ ] **Confirmation States**: Destructive actions (e.g. deleting a base, canceling custom request) require explicit confirmation dialogs.

---

## 3. Performance & Asset Gates

- [ ] **Server-First Boundary**: Pages default to React Server Components (RSC). `'use client'` is reserved strictly for interactive leaves.
- [ ] **Image Optimization**: All images render through `next/image` with explicit `width`, `height`, `sizes`, and modern formats (AVIF/WebP enabled). No oversized raw CDN images loaded without dimensions.
- [ ] **Request Minimization**: No duplicate or waterfall data fetching. Multiple sections on the same page share data via cached fetches or React `cache()`.
- [ ] **Bundle Weight Budget**: Core route initial JavaScript bundle stays under 100KB gzip. Heavy libraries (charts, rich text editors) are dynamically imported with `next/dynamic`.
- [ ] **Core Web Vitals Target**:
  - Largest Contentful Paint (LCP) < 2.5s.
  - Interaction to Next Paint (INP) < 200ms.
  - Cumulative Layout Shift (CLS) < 0.1.

---

## 4. Search Engine Optimization (SEO) Gates

- [ ] **Unique Metadata**: Every public route exports a dynamic `generateMetadata` or static `Metadata` object defining title, meta description, and canonical URL.
- [ ] **Open Graph & Twitter Cards**: Every shareable page (especially individual base layout cards) generates high-fidelity Open Graph (`og:image`, `og:title`, `og:description`) and Twitter cards.
- [ ] **Semantic Structure**: Exactly one `<h1>` per page. Heading hierarchy is strictly sequential (`h1` -> `h2` -> `h3`). Semantic tags used (`main`, `nav`, `article`, `header`, `footer`).
- [ ] **Indexing Directives**: Authenticated routes (`/profile`, `/checkout`, `/admin/*`) explicitly export `robots: { index: false, follow: false }`.
- [ ] **Structured Data (JSON-LD)**: Product schema on base pages, FAQPage schema on `/faq`, and Organization/WebSite schema on the homepage.
- [ ] **Robots & Sitemap**: Valid `robots.txt` and dynamic `sitemap.xml` generated by Next.js metadata routes.

---

## 5. Security & Data Protection Gates

- [ ] **Server-Side Validation**: All request bodies, query params, and route headers validated at the API boundary using Zod schemas.
- [ ] **Digital Delivery Protection**: Clash of Clans layout links (`link.clashofclans.com`) are strictly protected behind verified authentication and completed purchase records. Never leak layout links in public queries.
- [ ] **Role-Based Access Control (RBAC)**: All administrative endpoints and server actions verify `user.role === 'ADMIN'` on the server side. Never rely on client-side route hiding alone.
- [ ] **Secret Hygiene**: Zero environment secrets committed. Private API keys and database credentials never use the `NEXT_PUBLIC_` prefix.
- [ ] **Anti-Automation & Rate Limiting**: OTP generation, login attempts, and contact form submissions are protected by IP/user rate limiting.
- [ ] **Safe Error Messages**: Internal database exceptions, stack traces, and ORM errors are never sent in client-facing responses.

---

## 6. Accessibility (A11y) Gates

- [ ] **Keyboard Navigability**: Full keyboard navigation verified (`Tab`, `Shift+Tab`, `Enter`, `Space`, `Escape`). No keyboard traps.
- [ ] **Focus Visibility**: Visible, high-contrast focus rings (`focus-visible:ring-2`) on all interactive buttons, links, and form fields.
- [ ] **Color Contrast**: All text satisfies WCAG AA contrast ratio (4.5:1 for standard text, 3:1 for large headings). White text on yellow backgrounds is strictly forbidden.
- [ ] **Form Labels**: Every input has a corresponding `<label htmlFor="...">` or `aria-label`.
- [ ] **Screen Reader Compatibility**: Icon-only buttons include descriptive `aria-label` or visually hidden screen reader text (`sr-only`).
- [ ] **Reduced Motion Support**: All animations respect `prefers-reduced-motion: reduce`.
